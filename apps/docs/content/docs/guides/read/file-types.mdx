---
title: File types
description: Read images, notebooks, PDFs, and folders with converters, and decide which files count as text with classifiers.
---

The tool reads the first bytes of a file, and the `classifiers` decide its type from those bytes. Then:

- The first converter in `converters` that accepts the type reads the file.
- With no converter, the tool reads a text file as lines.
- With no converter, any other type returns status `unsupported`, with a note that names the type.

The default `converters` is `[]`, so by default the tool reads only UTF-8 text:

```text
[read:unsupported-pdf] This content is not supported as UTF-8 text. Use a PDF extraction tool.
```

A folder is refused with status `error` and code `NOT_A_FILE`, unless a converter lists it.

## Add converters

Set `converters` to a list. The first converter that accepts a file reads it:

```ts
import { nodeFileSystem } from "@better-fs-tools/node";
import { createReadTool, directoryListing, imageConverter, notebookConverter } from "@better-fs-tools/read";

const cwd = process.cwd();
const fs = nodeFileSystem({ cwd, allowedRoots: [cwd] });
const read = createReadTool({
  fs,
  converters: [imageConverter(), notebookConverter(), directoryListing()],
});
```

| Converter | Reads | Options |
| --- | --- | --- |
| `imageConverter()` | Images, as a media part | `transform` changes the bytes before they go to the model |
| `notebookConverter()` | Jupyter notebooks, as text | `outputs: false` leaves out cell outputs |
| `directoryListing()` | Folders, one entry for each line | `trailingSlash`, `sort: "name" \| "type-then-name"` |
| `textConverter()` | Any type, with your own function | See [Read PDFs and other formats](#read-pdfs-and-other-formats) |

Converted text works like a text file. `offset`, `limit`, the [limits](/guides/read/limits), and the continuation apply to the converted lines. `result.conversion` names the converter that read the file.

## Read images

With `imageConverter()`, an image returns status `media`. `result.content` holds the image:

```ts
const result = await read({ path: "docs/diagram.png" });

result.status; // "media"
result.content; // [{ type: "media", mediaType: "image/png", data: Uint8Array, name: "diagram.png" }]
```

The [AI SDK](/hosts/ai-sdk) and [Pi](/hosts/pi) integrations send the image to the model as a file part. In your own integration, send the media parts in the form your model API takes.

Set `transform` to make large images smaller. It gets the bytes and the media type, and returns new bytes of the same media type:

```ts
declare function resize(bytes: Uint8Array, mediaType: string, width: number): Promise<Uint8Array>;

imageConverter({ transform: (bytes, mediaType) => resize(bytes, mediaType, 1024) });
```

## Read notebooks

`notebookConverter()` gives each cell a header line, then its source, then its text outputs:

```text
1|[cell 1: markdown]
2|# Explore
3|
4|[cell 2: code]
5|1 + 1
6|[output]
7|2
```

## Read PDFs and other formats

`textConverter()` wraps your own text extractor, for example `pdftotext`, `pandoc`, or `markitdown`. `accepts` decides which files it reads. `run` gets the file bytes and returns the text:

```ts
import { textConverter } from "@better-fs-tools/read";

declare function pdfToText(source: AsyncIterable<Uint8Array>): AsyncIterable<string>;

const pdf = textConverter({
  id: "pdftotext",
  accepts: (match) =>
    match.classification.kind === "unsupported" && match.classification.code === "PDF",
  mimeType: "text/plain",
  run: (source) => pdfToText(source),
});
```

The converter runs again for each continuation, so cache the output if it is slow. A converter that starts a process needs Node or Bun, and does not work in a Cloudflare Worker.

`match.classification.code` is one of `BINARY`, `IMAGE`, `PDF`, `NOTEBOOK`, `OFFICE_DOCUMENT`, or `UNKNOWN_ENCODING`, or a code from your own classifier.

## List folders

`directoryListing()` lists a folder, one entry for each line. `offset` and `limit` then work on entries:

```ts
const read = createReadTool({
  fs,
  converters: [directoryListing({ trailingSlash: true, sort: "type-then-name" })],
});
```

```text
1|docs/
2|logs/
3|notebooks/
4|src/
5|.env
```

A listing stops at 200 entries. Set `limits.maxDirectoryEntries` to change this.

## Decide the file type

The default `classifiers` is `defaultClassifiers()`. It finds images, PDFs, Office documents, notebooks, and binary files, and it treats the rest as UTF-8 text. The first classifier that decides a type wins.

To decide by extension, put `extensionClassifier()` before the defaults:

```ts
import { defaultClassifiers, extensionClassifier } from "@better-fs-tools/read";

const read = createReadTool({
  fs,
  classifiers: [
    extensionClassifier({ unsupported: { ".log": { code: "BINARY" } }, text: [".lock"] }),
    ...defaultClassifiers(),
  ],
});
```

```text
[read:unsupported-binary] Files with the .log extension are not supported as UTF-8 text.
```

Keep `defaultClassifiers()` in the list. Without it, the tool does not find images, PDFs, or binary files.

Set `notes` on `defaultClassifiers()` to change the note for a type:

```ts
defaultClassifiers({
  notes: { PDF: { message: "PDFs are not supported here. Ask the user for a text copy." } },
});
```

## Size limits for converters

A converter reads at most 64 MiB of a file, and the media parts of one result can be at most 5 MiB. Past these limits, the read returns status `unsupported` with code `TOO_LARGE`. Set `limits.maxConvertBytes` and `limits.maxMediaBytes` to change them.

## Write your own converter

A file converter is an object with an `id`, `target: "file"`, an `accepts(match)` function, and an async `convert(input, ctx)` function. `convert` returns one of:

- `{ kind: "text", text, mimeType }`, where `text` is a string or an async iterable of strings
- `{ kind: "media", parts }` with media parts
- `{ kind: "refuse", code, note }` to refuse the file

A folder converter has `target: "directory"` and no `accepts`. Use `textConverter()` when your converter returns text. The [read reference](/reference/read#converter) lists every field.
