## Use the format of another harness

If your model was tuned on another harness, give it the read output it knows:

```ts
import { createNodeReadTool } from "@better-fs-tools/node";
import { opencodeFormat } from "@better-fs-tools/read/formats";

const read = createNodeReadTool({ formatter: opencodeFormat() });

await read({ path: "src/greet.ts", limit: 3 });
```

```text
<path>src/greet.ts</path>
<type>file</type>
<content>
1: export function greet(name: string): string {
2:   return `Hello, ${name}!`;
3: }
</content>

[read:continue] Output stopped at the line limit. Continue with {"path":"src/greet.ts","offset":4,"limit":3}.
```

For the same read, `deepAgentsFormat()` gives a range header and plain lines:

```text
@@ lines 1-3 of 7 | next offset 4 @@
export function greet(name: string): string {
  return `Hello, ${name}!`;
}
@@ lines 1-3 of 7 | next offset 4 @@
```

`hermesFormat()` gives one JSON object:

```text
{"content":"1|export function greet(name: string): string {\n2|  return `Hello, ${name}!`;\n3|}","total_lines":7,"file_size":158,"truncated":true,"next_offset":4,"hint":"Output stopped at the line limit. Continue with {\"path\":\"src/greet.ts\",\"offset\":4,\"limit\":3}."}
```

`hashlineFormat()` is in the next section.

## Add line hashes and a file hash

Hashes let a model check that a line has not changed since it read it:

```ts
import {
  eofFooter,
  fileHashHeader,
  hashlineGutter,
  lineNumberFormatter,
} from "@better-fs-tools/read";

const read = createNodeReadTool({
  formatter: lineNumberFormatter({
    gutter: hashlineGutter({ width: 2 }),
    header: fileHashHeader(),
    footer: eofFooter((n) => `(End of file - total ${n} lines)`),
  }),
});
```

```text
file-hash: sha256:1ccd45e39bd9ff6fc370d097d7b33bc92d915241f3ac7ec77298a883e1b38ae7
1:2b|export function greet(name: string): string {
2:04|  return `Hello, ${name}!`;
3:d1|}
4:e3|
5:03|export function farewell(name: string): string {
6:51|  return `Goodbye, ${name}!`;
7:d1|}
(End of file - total 7 lines)
```

The footer shows only when the read gets to the end of the file. `hashlineFormat()` from `@better-fs-tools/read/formats` gives the same layout with its own footer text.

## Show the text with no line numbers

`plainFormatter()` gives the source as it is, so the model can copy it into an edit:

```ts
import { plainFormatter } from "@better-fs-tools/read";

const read = createNodeReadTool({ formatter: plainFormatter() });
```

```text
export function greet(name: string): string {
  return `Hello, ${name}!`;
}

[read:continue] Output stopped at the line limit. Continue with {"path":"src/greet.ts","offset":4,"limit":3}.
```

## Return JSON

`jsonFormatter()` gives JSON text. `pick` chooses the fields:

```ts
import { jsonFormatter } from "@better-fs-tools/read";

const read = createNodeReadTool({
  formatter: jsonFormatter({
    pick: (outcome) => ({
      status: outcome.status,
      lines: outcome.status === "ok" ? outcome.view.lines.map((line) => line.text) : [],
      nextOffset: outcome.status === "ok" ? (outcome.continuation.next?.offset ?? null) : null,
    }),
    space: 2,
  }),
});
```

```text
{
  "status": "ok",
  "lines": [
    "export function greet(name: string): string {",
    "  return `Hello, ${name}!`;"
  ],
  "nextOffset": 3
}
```

With no `pick`, the JSON holds the whole result. Pass `notes: "after"` to print the notes as text lines after the JSON.

## Change the wording of a note

Pass `messages` with the notes you want to change. The others keep their default text:

```ts
const read = createNodeReadTool({
  messages: {
    notFound: ({ request }) => `No file at ${request.path}. List the folder first.`,
    continuation: ({ retry }) => `More lines follow. Call read with ${retry}.`,
  },
});
```

```text
[read:not-found] No file at docs/setpu.md. List the folder first.
```

```text
1|export function greet(name: string): string {
2|  return `Hello, ${name}!`;

[read:continue] More lines follow. Call read with {"path":"src/greet.ts","offset":3,"limit":2}.
```

The [read reference](/reference/read) lists every message.

## Hide a note or change how notes look

The `notes` option of `lineNumberFormatter()` can hide a note from the model. Return `null` to hide it:

```ts
const read = createNodeReadTool({
  formatter: lineNumberFormatter({
    notes: (note) => (note.code === "clamped" ? null : note),
  }),
});
```

The note stays in `result.notes`, so your code can still read it.

`noteLine` sets how each note is printed:

```ts
const read = createNodeReadTool({
  formatter: lineNumberFormatter({
    noteLine: (note) => `<note code="${note.code}">${note.message}</note>`,
  }),
});
```

```text
1|export function greet(name: string): string {
2|  return `Hello, ${name}!`;

<note code="continue">Output stopped at the line limit. Continue with {"path":"src/greet.ts","offset":3,"limit":2}.</note>
```

`lineNumberFormatter()` also takes `gutter` for the line prefix, `clampMarker` for the text after a cut line, and `header` and `footer`.

## Write your own formatter

A formatter is an object with a `format(outcome, ctx)` function. It returns a string or a list of content parts. It must be synchronous, and it cannot read files. If it throws, the model gets the default format and an `extension-failed` note.
