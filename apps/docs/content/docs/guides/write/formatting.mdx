---
title: Customise formatting
description: Show the diff, change the layout and the wording of notes, or write your own formatter for the write tools.
---

A formatter turns the result of a call into `result.content`, the parts that go to the model. The default is `defaultWriteFormatter()`. The formatter changes only `content`. `status`, `changes`, `notes`, and the other fields stay the same.

## What the default shows

The default prints one line that tells what changed, then a blank line and the notes. A failed call prints only the notes:

| Tool          | First line                                                                | Then                                                                     |
| ------------- | ------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| `edit`        | `Edited src/greet.ts: 1 replacement at line 2.`                           | The new lines around each change, with the `2\|` gutter of the read tool |
| `write`       | `Created src/names.ts (1 line).` or `Updated src/greet.ts (+2 -5 lines).` | Nothing                                                                  |
| `apply_patch` | `Success. Updated the following files:`                                   | One line for each file: `A`, `M`, or `D`, and the path                   |

A `no-change` result prints `No change to src/greet.ts.`

## Change the layout

`defaultWriteFormatter()` takes three options:

| Option     | Default               | Sets                                                        |
| ---------- | --------------------- | ----------------------------------------------------------- |
| `diff`     | `false`               | `true` adds the unified diff of each file in a fenced block |
| `gutter`   | `` (n) => `${n}\|` `` | The text before each line of an `edit` snippet              |
| `noteLine` | `[tool:code] message` | How each note is printed. Gets the note and the tool name   |

```ts
import { nodeFileSystem } from "@better-fs-tools/node";
import { createEditTool, defaultWriteFormatter } from "@better-fs-tools/write";

const cwd = process.cwd();
const fs = nodeFileSystem({ cwd, allowedRoots: [cwd] });
const edit = createEditTool({ fs, formatter: defaultWriteFormatter({ diff: true }) });
```

`edit` shows 3 lines of context around each change, and at most 40 lines for each file. Set `limits.snippetLines` and `limits.maxSnippetLines` to change this. The full diff is always in `result.changes[].diff`, cut at `limits.maxDiffLines`.

## Change the wording of notes

Set `messages` to change the text of a note. Each message is a function that gets the details of the note and returns a string. The messages you leave out keep their default text:

```ts
const edit = createEditTool({
  fs,
  messages: {
    notFound: ({ path }) => `No file at ${path}. Create it with the write tool.`,
  },
});
```

```text
[edit:not-found] No file at src/missing.ts. Create it with the write tool.
```

The note `code` does not change, so key your code on `code`, not on the text. The [write reference](/reference/write#messages) lists every message and its arguments.

Many messages name a parameter, for example `the oldText was not found`. When a [signature](/hosts/tool-definition) renames the parameters, pass `messages: writeSignatureMessages(signature)` from `@better-fs-tools/write/signature`. The notes then use the names that the model sees. The provider integrations do this for you.

## Write your own formatter

A formatter is an object with an `id` and a `format(report, ctx)` function. `format` returns a string, or a list of content parts. It must be synchronous:

```ts
import type { WriteFormatter } from "@better-fs-tools/write";

const summary: WriteFormatter<unknown> = {
  id: "summary",
  format: (report) =>
    report.status === "error"
      ? report.error.message
      : report.changes
          .map((c) => `${c.kind} ${c.path} +${c.linesAdded} -${c.linesRemoved}`)
          .join("\n"),
};
```

```text
update src/greet.ts +1 -1
```

`report` is the result without `content`. `ctx` holds the `digest`, the `limits`, and the call context in `call`. Narrow on `report.status` before you read `report.error`.

If your formatter throws, the tool uses `defaultWriteFormatter()` and adds a note. The change is not lost:

```text
[edit:extension-failed] The summary formatter failed, so the default formatter formatted this result.
```
