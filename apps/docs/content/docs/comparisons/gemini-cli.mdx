Gemini CLI is Google's open-source terminal coding agent. Its model-facing file family is seven dedicated tools, `read_file`, `read_many_files`, `list_directory`, `glob`, `grep_search`, `replace`, and `write_file`, plus `run_shell_command` and two background-process readers. The tool declarations come in two sets chosen by model family: a default-legacy set for every model outside the Gemini 3 family, and a Gemini 3 set whose `read_file`, `write_file`, `grep_search`, and `replace` strings differ. Paths are canonicalised and checked against the workspace roots before any I/O, and a central policy engine decides which calls need confirmation.

## Read

### Signature

```ts
read_file({ file_path: string, start_line?: integer, end_line?: integer })
read_many_files({ include: string[], exclude?: string[], recursive?: boolean, useDefaultExcludes?: boolean, file_filtering_options?: { respect_git_ignore?: boolean, respect_gemini_ignore?: boolean } })
```

`file_path` is relative or absolute; a relative path resolves against the target directory. `start_line` and `end_line` are one-based and inclusive, typed as integers with minimum 1. With neither, the first 2000 lines are returned. With `start_line` alone, 2000 lines from that line. `end_line` past the end is clamped. `start_line` greater than `end_line` fails validation with `start_line cannot be greater than end_line`. The parameter names and types are identical in both declaration sets.

### Description

`read_file`, default-legacy: 444 characters, 444 bytes, 1 line, approximately 111 tokens.
`read_file`, Gemini 3 family: 552 characters, 552 bytes, 1 line, approximately 131 tokens.
`read_many_files`: 1936 characters, 1936 bytes, 10 lines, approximately 401 tokens. Identical in both sets.

**`read_file`, default-legacy (444 characters)**

```text

The tool's response will clearly indicate if truncation has occurred and will provide details on how to read more of the file using the 'start_line' and 'end_line' parameters. Handles text, images (PNG, JPG, GIF, WEBP, SVG, BMP), audio files (MP3, WAV, AIFF, AAC, OGG, FLAC), and PDF files. For text files, it can read specific line ranges.
```

The Gemini 3 set is selected when `isGemini3Model()` matches the active model ID.

For your safety, the tool will automatically truncate output exceeding 2000 lines, 2000 characters per line, or 20MB in size; however, triggering these limits is considered token-inefficient. Always retrieve only the minimum content necessary for your next step. Handles text, images (PNG, JPG, GIF, WEBP, SVG, BMP), audio files (MP3, WAV, AIFF, AAC, OGG, FLAC), and PDF files.

**`read_many_files` (1936 characters)**

```text
Reads content from multiple files specified by glob patterns within a configured target directory. For text files, it concatenates their content into a single string. It is primarily designed for text-based files. ### Path handling
```

`resolveDefensiveToolPath` removes NUL bytes and strips a leading `@` when the literal path does not exist and no `@`-prefixed entry exists for the first segment. `resolveToRealPath` accepts a `file://` URL, percent-decodes the string, resolves it against the target directory, and takes the real path with `realpathSync`; for a missing leaf it resolves the existing symlink ancestors. No tilde expansion. Symlinks are followed before the workspace check, so a link inside the workspace whose target is outside fails the check. A real-path failure returns `Failed to resolve path: <message>`.

Near-miss recovery: None. A missing file returns:

```text
File not found: <path>
```

The message travels in the function response `error` field. The tool's `llmContent` for that case, `Could not read file because no file was found at the specified path.`, is dropped by the executor when an error is set; see Errors.

### Notable

- After the content, JIT context discovered for the file's directory can be appended between `--- Newly Discovered Project Context ---` and `--- End Project Context ---`, so the result can carry `GEMINI.md` text that is not in the requested file.
- No repeat-read guard, no redaction, no explicit empty-file notice. An empty file returns an empty string.
- `read_file` does not read the abort signal; `execute` ignores its options.
- The UI summary for a ranged read is `Read lines <a>-<b> of <total> from <rel>`; a plain full read shows nothing.
- `read_many_files` expands `include` in every workspace directory, filters through the discovery service, validates each path, sorts, and processes files with `Promise.allSettled`. Text goes out under `--- <path> ---` separators with `--- End of content ---` after the last file. Skipped files are reported by path and reason; the reason strings: Not surveyed. There is no shared snapshot across the files.
- The scheduler runs `read_file` calls in parallel with other parallelizable calls unless the model sets `wait_for_previous`.

## Edit

### Signature

```ts
write_file({ file_path: string, content: string })
replace({ file_path: string, old_string: string, new_string: string, instruction: string, allow_multiple?: boolean })
```

The model name is `replace`; the source class is `EditTool`. `instruction` is required and is only used by the optional LLM correction path. `allow_multiple` is a boolean. There is no delete tool and no multi-file patch tool. `replace` and `write_file` are in `EDIT_TOOL_NAMES`, which the scheduler treats as ordered barriers. Both declaration sets share the parameter names and types; the Gemini 3 set shortens the parameter-level descriptions.

`write_file`, Gemini 3 family: 304 characters, 304 bytes, 1 line, approximately 59 tokens.
`replace`, default-legacy: 2063 characters, 2063 bytes, 12 lines, approximately 421 tokens.
`replace`, Gemini 3 family: 571 characters, 571 bytes, 2 lines, approximately 111 tokens.

**`write_file`, Gemini 3 family (304 characters)**

**`replace`, default-legacy (2063 characters)**

```text
Replaces text within a file. By default, the tool expects to find and replace exactly ONE occurrence of `old_string`. If you want to replace multiple occurrences of the exact same string, set `allow_multiple` to true. This tool requires providing significant context around the change to ensure precise targeting. Always use the read_file tool to examine the file's current content before attempting a text replacement.
```

### Whole-file write

`write_file` validates the path, rejects a directory target with `Path is a directory, not a file: <path>`, and rejects content that holds an omission placeholder such as `rest of methods ...`. The confirmation step reads the current file, builds a unified diff, and lets the user change the content. Execution reads the file again, creates missing parent directories, and calls `StandardFileSystemService.writeTextFile`, which is `fs.writeFile(path, content, 'utf-8')`. The write is direct: no temporary file, no rename, no mode preservation, no post-write verification. Line endings: when the existing file used CRLF, every line ending in the new content is converted to CRLF; for a new file the OS default applies. BOM: the service reads and writes UTF-8 as-is, so an existing BOM survives only if the model's content contains it. In plan mode the path is redirected into the plans directory.

Content correction: with `disableLLMCorrection` at its default `true`, no model call is made. An unescape pass still runs for models outside the Gemini 2 and Gemini 3 families and custom models; Gemini 2 and 3 models get the content as supplied. JSON and notebook files skip the pass.

### Matching

`replace` reads the file once inside the call, normalises CRLF to LF, and runs a cascade: exact, then line-trimmed flexible, then a token regex that allows whitespace between tokens, then a bounded Levenshtein fuzzy match for `old_string` of at least ten characters with a 10 percent weighted difference limit and a work cap of `lines * length^2 <= 4e8`. The first strategy that finds a candidate wins. Without `allow_multiple` the count must be exactly one. A fuzzy match is reported to the model as `Applied fuzzy match at line <n>.` or `lines <a>-<b>`; flexible and regex matches are not reported. An empty `old_string` creates the file when it does not exist and errors when it does. Equal `old_string` and `new_string` is an error. Validation completes before the write, so a miss leaves the file unchanged.

When every strategy misses and `disableLLMCorrection` is `false`, `FixLLMEditWithInstruction` asks a secondary model for a corrected pair. The path hashes the first read, re-reads the file, and uses the newer content when the hash changed. JSON, JSONC, JSON5, and notebook files skip correction. The setting defaults to `true`, so this path is off unless the user enables it. The correction prompt itself: Not surveyed.

### Multi-file patch

None. `replace` covers one file per call. There is no patch grammar and no multi-file tool.

### Verification and mutation state

| Concern | Behaviour |
|---|---|
| Read-before-write | Described to the model in the default-legacy `replace` string; not enforced. `write_file` accepts any destination |
| Stale-file check | None on the normal path. The LLM-correction path compares a SHA-256 of the in-call read against a re-read, only when correction is enabled and the first match failed |
| Lock | None. The scheduler forces `replace` and `write_file` into ordered barriers within one batch; there is no path lock shared with `run_shell_command`, background processes, or other CLI instances |
| Cross-process coordination | None |
| Post-write checks | None. No syntax or LSP check |
| Change tracking | Build-file writes are recorded for a later reminder; the UI receives a diff and diff statistics |

### Output

| Tool | Model text |
|---|---|
| `write_file` | `Successfully created and wrote to new file: <path>.` or `Successfully overwrote file: <path>.`, then `Here is the updated code:` and a five-line diff context snippet. ``User modified the `content` to be: <content>`` is inserted when the user edited the content |
| `replace` | `Created new file: <path> with provided content.` or `Successfully modified file: <path> (<n> replacements).`, then `Here is the updated code:` and the snippet, then the fuzzy-match note when it applies, then ``The confirmation step modified the `new_string` content to be: <text>.`` when the user edited it |

JIT project context can follow either message. The full unified diff, diff statistics, and the `isNewFile` flag go to `returnDisplay` for the UI, not to the model.

### Notable

- The confirmation for both tools shows a diff and can open the IDE diff view; the user can alter the proposed content before it is written, and the model is told.
- No notebook editor, no undo tool, no checkpoint tool in this family.
- The `replace` description promises exact matching; the runtime accepts the flexible, regex, and fuzzy cascade above.
- `write_file` and `replace` in `autoEdit` mode are allowed after an in-process `allowed-path` safety checker; in `plan` mode the read-only policy denies them.
- The default-legacy `write_file` description says nothing about parent creation or overwrite; the runtime does both.

## Shell

### Signature

```ts
run_shell_command({ command: string, description?: string, dir_path?: string, is_background?: boolean, delay_ms?: integer, additional_permissions?: object })
```

### Working directory and environment

The working directory is the target directory unless `dir_path` is given; the resolved directory must pass `validatePathAccess`. Unix commands run as `bash -c <command>`; Windows uses the configured PowerShell or command shell path. `ShellExecutionService` sanitises the environment, sets `GEMINI_CLI=1`, disables Git credential and interactive prompts, applies pager defaults, and asks the configured `SandboxManager` to prepare the command. On non-Windows hosts the command is wrapped with a POSIX `EXIT` trap that records child background PIDs to a temp file. Login shell: None.

### Process lifecycle

| Aspect | Behaviour |
|---|---|
| Model | One process per call. `node-pty` when the interactive shell is enabled and a PTY implementation loads, otherwise `child_process`. The child leads its own process group on supported Unix systems, except under Bun |
| Background | `is_background` starts the process, waits `delay_ms`, and returns `Command is running in background. PID: <pid>. Initial output:` with the output so far when the process is still running. The execution stays managed in `ShellExecutionService`; completion can inject output into the conversation or stay silent |
| stdin | The UI can write input to an active PTY; the model cannot |
| Cancellation | Abort or inactivity timeout kills the process group with escalation and waits for the close event |
| Grandchildren | PIDs captured by the `EXIT` trap are reported as `Background PIDs:`; they are not managed unless `is_background` was used |
| Late exits | The lifecycle service keeps exit information for five minutes; the session history holds at most 100 records |

The inactivity timeout comes from `tools.shell.inactivityTimeout`, 300 seconds by default; any output, binary-progress, or exit event resets it. A timeout returns `Command was automatically cancelled because it exceeded the timeout of <n> minutes without output.` followed by ` Below is the output before it was cancelled:` and the output, or ` There was no output before it was cancelled.`

### Output limits

| Aspect | Behaviour |
|---|---|
| Collection | stdout and stderr are decoded separately and appended to one ordered string. The child-process buffer keeps at most 16 MiB as a rolling tail and appends `[GEMINI_CLI_WARNING: Output truncated. The buffer is limited to 16MB.]` when it overflowed. PTY mode uses xterm scrollback up to 300 000 lines |
| Live buffer | 100 000 characters for UI updates, refreshed at most once per second |
| Binary output | A 4 KiB sniff; a binary stream stops text rendering and shows `[Binary output detected. Halting stream...]`, then byte-count progress |
| Model-visible budget | The scheduler saves `run_shell_command` text above `truncateToolOutputThreshold`, 40 000 characters by default, to `tool-outputs/` under the project temp directory and returns `Output too large. Showing first 8,000 and last 32,000 characters. For full output see: <file>` with the head and tail around `... [<n> characters omitted] ...`. With context management on, `ToolOutputDistillationService` can summarise instead |
| Spill file | `<projectTempDir>/tool-outputs/session-<sessionId>/<tool>_<callId>.txt`. No cleanup deadline in the source |
| Empty output | `(empty)` |
| Wrapper | The whole shell result is wrapped in an `untrusted_context` tag pair before it reaches the model |

### Sandbox

Optional. A full-process sandbox is selected by `--sandbox`, `GEMINI_SANDBOX`, or settings, with Docker, Podman, macOS Seatbelt, gVisor, LXC, and a Windows native sandbox as providers; container and LXC modes mount the workspace at its host path. Tool-level sandboxing adds a `SandboxManager` preparation step to shell execution only: Bubblewrap on Linux and Seatbelt on macOS can deny writes outside the workspace, protect `.git`, hide secret files such as `.env`, and grant paths from `additional_permissions`. A denial can return `Sandbox expansion required` with a structured request so the model can retry with narrower added paths or network access. Without a selected sandbox, `NoopSandboxManager` runs and only sanitises the environment; `LocalSandboxManager` throws `Tool sandboxing is not yet implemented.`. Direct `read_file`, `write_file`, and `replace` calls never pass through the sandbox manager.

### Approval

`run_shell_command` is `ask_user` at priority 10 in `policies/write.toml`. Confirmation shows the parsed root commands, redirections, untrusted flags, and any sandbox expansion, and can produce an allow-once, allow-session, or persistent rule narrowed to a command prefix. Before execution `detectCommandSubstitution` blocks `$()`, backticks, `<()`, and `>()` in command arguments, and PowerShell `@()` and `$()`, with `Command injection detected: command substitution syntax ($(), backticks, <() or >()) found in command arguments. ...` as success text. `yolo` allows most tools; `plan` denies through the read-only policy; an untrusted folder disables `yolo` and `autoEdit`. In a non-interactive session the policy engine's default decision is deny. No shipped policy rule names the two background tools, so they take the engine default, `ask_user` in an interactive session. The confirmation text shown to the user: Not surveyed.

### Notable

- A non-zero exit is a successful tool result. The model text is `Output: <text>` then `Exit Code: <n>`, with `Signal: <sig>`, `Background PIDs: <pids>`, and `Process Group PGID: <pgid>` lines when present. Only a spawn failure sets the `error` field.
- User cancellation returns `Command was cancelled by user before it could complete.` plus the output-before-cancel clause, or `Command was cancelled by user before it could start.` when the signal was already set.
- `read_background_output` checks that the PID belongs to the session, opens the predicted log with `O_NOFOLLOW`, reads at most 64 KiB from the end, and returns `Showing last <n> of <total> lines:` with the tail. A missing record returns `Access denied. Background process ID <pid> not found in this session's history.`; a symlink at the log path returns `Symbolic link detected at predicted log path. Access is denied for security reasons.`
- `list_background_processes` returns `No background processes found.` or one ``- [PID <pid>] <STATUS>: `<command>` `` line per record.
- The default-legacy and Gemini 3 sets call the same shell description helper, so shell text does not change with the model family.

## Search and listing

### Tools

| Tool | Arguments | Default caps | Ignore rules |
|---|---|---|---|
| `glob` | `pattern`, `dir_path?`, `case_sensitive?`, `respect_git_ignore?`, `respect_gemini_ignore?` | None in the leaf. Files modified in the last 24 hours first, newest first, then the rest alphabetically | `dot: true`, `follow: false`, `nodir: true`; configured exclusions plus `.gitignore` and `.geminiignore` through the discovery service |
| `grep_search` (ripgrep) | `pattern`, `dir_path?`, `include_pattern?`, `exclude_pattern?`, `names_only?`, `case_sensitive?`, `fixed_strings?`, `context?`, `before_context?`, `after_context?`, `no_ignore?`, `max_matches_per_file?`, `total_max_matches?` | 100 total matches; 2000 characters per line with `... [truncated]`; 30 second timeout floor, raised by `searchTimeout` | `rg --json`; `.gitignore` native; `.geminiignore` through `--ignore-file`; common directory excludes, `*.log`, `*.tmp`; `no_ignore` disables all of them |
| `list_directory` | `dir_path`, `ignore?`, `file_filtering_options?` | None. No offset, limit, or page | `.gitignore` and `.geminiignore` by default; per-call `ignore` globs on the basename |
| Stat, find, mkdir | None | | |

`glob` searches every workspace root when `dir_path` is omitted, escapes a pattern that names an existing path, resolves results to real paths, and returns `Found <n> file(s) matching "<pattern>" within <dir>, sorted by modification time (newest first):` with absolute paths one per line, or `No files found matching pattern "<pattern>" within <dir>`. An ignored count is appended in parentheses. `grep_search` returns `Found <n> match(es) for pattern "<pattern>" in path "<dir>":` then blocks of `File: <path>` and `L<line>: <text>` rows between `---` lines; context lines use `L<line>- <text>`. With `names_only` it lists paths. When one to three matches are found and no context was requested, the ripgrep path re-runs with 50 context lines for one match or 15 for two or three. Zero matches return `No matches found for pattern "<pattern>" ...`. The `GrepTool` fallback tries `git grep`, then system `grep`, then a JavaScript scan, and parses `path:line:content` text; its output shape: Not surveyed. `list_directory` returns `Directory listing for <dir>:` with `[DIR] <name>` rows first, then `<name> (<size> bytes)` rows, alphabetical within each group, plus `(<n> ignored)` when entries were filtered. An empty directory returns `Directory <dir> is empty.` Entries that fail `stat` are omitted without a notice.

### Description

`list_directory`: 150 characters, 150 bytes, 1 line, approximately 24 tokens. Identical in both sets.
`glob`: 261 characters, 261 bytes, 1 line, approximately 55 tokens. Identical in both sets.
`grep_search`, default-legacy: 63 characters, 63 bytes, 1 line, approximately 11 tokens.
`grep_search`, Gemini 3 family: 301 characters, 301 bytes, 1 line, approximately 61 tokens.

**`list_directory` (150 characters)**

```text
Lists the names of files and subdirectories directly within a specified directory path. Can optionally ignore entries matching provided glob patterns.
```

**`glob` (261 characters)**

```text
Efficiently finds files matching specific glob patterns (e.g., `src/**/*.ts`, `**/*.md`), returning absolute paths sorted by modification time (newest first). Ideal for quickly locating files based on their name or path structure, especially in large codebases.
```

**`grep_search`, default-legacy (63 characters)**

```text
Searches for a regular expression pattern within file contents.
```

**`grep_search`, Gemini 3 family (301 characters)**

Selected with the Gemini 3 declaration set.

```text
Searches for a regular expression pattern within file contents. This tool is FAST and optimized, powered by ripgrep. PREFERRED over standard `run_shell_command("grep ...")` due to better performance and automatic output limiting (defaults to 100 matches, but can be increased via `total_max_matches`).
```
