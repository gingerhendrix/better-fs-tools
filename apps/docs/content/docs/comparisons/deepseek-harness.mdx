DeepSeek Harness is an open-source coding agent published by DeepSeek as the `@deepseek-ai/dsh` npm package. It is a developer preview. Every part of it is a Cordis plugin, including each tool, so the model-facing tool set is a composition choice. The default composition offers ten filesystem and shell tools: `read`, `read_image`, `write`, `edit`, `glob`, `grep`, `bash`, and the three `job_*` tools that collect background commands. Descriptions are one or two sentences each, and cross-call guidance lives in system prompt sections. Four things mark this harness: a read-before-mutate policy with stale-version checks, a literal unique-match edit, an OS-level file sandbox around `bash`, and a same-turn escalation flow for sandbox denials. This page describes the `dsh` CLI with the shipped `dsh-base` bundle rows and the `standard` agent preset on a POSIX host; the web and desktop hosts run the same core through the same rows.

## Read

### Signature

```ts
read({ file_path: string, offset?: number, limit?: number })
read_image({ file_path: string })
```

`file_path` is relative or absolute. `offset` is one-based and defaults to `1`. `limit` defaults to 2000 and is also the ceiling: a larger value is an error. Both must be positive integers. The schema types them as `number`.

### Description

`read`: 56 characters, 56 bytes, 1 line, approximately 14 tokens.
`read_image`: 545 characters, 545 bytes, 1 line, approximately 101 tokens.

The `read` string says only that the file is UTF-8 text and the result is line-numbered. The 2000-line default is in the `limit` parameter description, rendered from the `readLimit` config. The rest of the guidance is a system prompt section: use `read` rather than `cat`, results carry line numbers, use `offset` and `limit` to continue. `read_image` names the four formats, says extension-less files are sniffed, says the harness downscales large images, asks for small concurrent batches, and states the image-capable-model requirement.

**`read` (56 characters)**

```text
Read a UTF-8 text file and return line-numbered content.
```

**`read_image` (545 characters)**

```text
Read a PNG/JPEG/WebP/GIF file and return the image itself. A path without a file extension is accepted; the format is detected from the file content, so normalized attachment paths can be passed directly without copying or renaming. Harness validates and downscales large supported images before the next model request, so use this tool directly instead of installing image libraries or creating thumbnails merely to inspect an image. Independent files may be read concurrently in small batches. Requires the current model to accept image input.
```

### Path handling

Relative paths resolve against the calling session's workspace (`session.header.cwd`), which the web host sets per session and the `fs-sandbox` row defaults to `process.cwd()`. There is no `~` expansion and no URL handling. A path containing `..` keeps its physical spelling on POSIX. The backend resolves the file's `realpath` as its identity key, so two spellings of one file share stale-version guards and observation state; the display path keeps the spelling the model gave. For a missing file the nearest existing ancestor is resolved and the missing suffix appended.

Near-miss recovery: None. A miss is:

```text
cannot read "<path>": not found
```

Symlinks: followed. Reads are not confined; the sandbox fence applies to mutations only.

### Permissions

| Check | Behaviour |
|---|---|
| Path rules | None. Every sandbox mode permits reading any path the process can open |
| Approval | None for reads |
| Device and special files | A `stat` type other than `file` is refused with `cannot read "<path>": not a regular file`. Directories, FIFOs, and device nodes fall under this |
| Observation | A successful read, and a miss, are recorded per session and target so a later `write` or `edit` can prove it followed a read |
| Denial text | Not applicable |

### Binary and conversion

| Aspect | Behaviour |
|---|---|
| Detection | A NUL byte in the first 8192 bytes, or invalid UTF-8 anywhere |
| Refusal | `cannot read "<path>": binary file`; `cannot read "<path>": invalid UTF-8 text` |
| Notebooks | None. `.ipynb` reads as JSON text |
| Office and PDF text | None |
| Images | Through `read_image` only. Extension `.png`, `.jpg`, `.jpeg`, `.webp`, `.gif`, or no extension with a magic-byte sniff. The bytes are saved to the attachment store, downscaled to a 2048 by 2048 pixel budget when larger, and returned as an image block beside a text envelope |
| Image limits | 20 MiB per file; 8192 pixels per side; 64 million pixels decoded; a 16-bit PNG that fails conversion is refused |
| Audio and video | None |
| Encoding | UTF-8 only, fatal decoder. No BOM handling: a BOM stays in line one. A trailing `\r` is stripped from each line |

### Limits

| Limit | Value | Message |
|---|---|---|
| Default window | 2000 lines | |
| Ceiling | 2000 lines | `limit must be less than or equal to 2000` |
| Long line | Cut at 2000 characters | `... (line truncated to 2000 chars)` appended to the line |
| Output budget | 50 KiB of selected lines; the scan stops there | `(Output capped. Showing lines <a>-<b>. Use offset=<n> to continue.)` |
| Whole-file size | None. Files of 10 MiB and above stream; smaller files load whole | |
| Offset past end | Error, except offset 1 on an empty file | `offset <n> is out of range for "<path>" (<total> lines)` |

The total line count is exact even when the window is capped, because the scan continues past the cap to count lines.

### Output

```text
<path>/repo/src/app.ts</path>
<type>file</type>
<content>
1: import { x } from "./x"
2: export const y = x

(End of file - total 2 lines)

```

| Aspect | Behaviour |
|---|---|
| Prefix before content | `path`, `type`, and `content` tags; content starts on the line after the opening `content` tag |
| Line prefix | `N: text`, unpadded |
| End marker | `(End of file - total <n> lines)` after a blank line, then the closing `content` tag |
| Truncation notice | Replaces the end marker: `(Showing lines <a>-<b> of <total>. Use offset=<n> to continue.)` at the line limit; `(Output capped. Showing lines <a>-<b>. Use offset=<n> to continue.)` at the byte cap |
| Error transport | Thrown; the registry returns one text block `Error: <message>` with `isError: true` and a structured `error` field carrying the `FS_*` code |

The example is reconstructed from `formatReadOutput` in `read-render.ts`. An empty file returns the envelope with only `(End of file - total 0 lines)` inside.

### Notable

- `read` is exempt from the `spill-policy` result cap so a large read does not spill to a file that the model then reads again.
- No repeat-read guard, no content injection after the read, no redaction.
- Reads are marked concurrency-safe, so a batch of `read` calls runs in parallel; mutations run exclusively.
- `read_image` refuses before any I/O when the routed model does not declare `image` input: `cannot read "<path>" as an image: model "<model>" does not declare image input; switch to an image-capable model to read images`.
- The `read_image` envelope reports `<mediaType> image, <w>x<h> px, <bytes> bytes` and, after a downscale, the original size and a coordinate multiplier.
- A compaction-time pruner (`tool-result-pruner`, threshold 8192 characters, head 4096, tail 1024) can later shorten old tool results in history; it does not change the live result.

## Edit

### Signature

```ts
write({ file_path: string, content: string, sandbox_permissions?: string, justification?: string })
edit({ file_path: string, old_string: string, new_string: string, replace_all?: boolean, sandbox_permissions?: string, justification?: string })
```

`replace_all` defaults to `false`. `old_string` must be non-empty and must differ from `new_string`. The two escalation fields are advertised only when a confining filesystem is mounted, which the surveyed composition does; `sandbox_permissions` is an enum of `workspace-write` and `danger-full-access`. There is no patch tool and no delete tool in the default set. `str_replace_editor` is a separate opt-in tool with `command`, `path`, `file_text`, `insert_line`, `new_str`, `old_str`, and `view_range`.

### Description

`write`: 42 characters, 42 bytes, 1 line, approximately 11 tokens.
`edit`: 59 characters, 59 bytes, 1 line, approximately 13 tokens.
`str_replace_editor`: 1119 characters, 1119 bytes, 11 lines, approximately 249 tokens. Opt-in; the default `description` config of `tool-str-replace-editor`, which a row can replace.

`write` and `edit` are one sentence each. The read-first rule, the uniqueness rule, and the `replace_all` advice are in system prompt sections registered by the same plugin, not in the description. `str_replace_editor` describes `view`, `create`, `str_replace`, and `insert`, the `cat -n` view format, a two-level directory listing, the `<response clipped>` marker, and the exact-match and uniqueness rules for `old_str`.

**`write` (42 characters)**

```text
Create or fully replace a UTF-8 text file.
```

**`edit` (59 characters)**

```text
Edit an existing UTF-8 text file by replacing literal text.
```

**`str_replace_editor` (1119 characters, opt-in)**

```text
Custom editing tool for viewing, creating and editing files
* State is persistent across command calls and discussions with the user
* If `path` is a file, `view` displays the result of applying `cat -n`. If `path` is a directory, `view` lists non-hidden files and directories up to 2 levels deep
* The `create` command cannot be used if the specified `path` already exists as a file
* If a `command` generates a long output, it will be truncated and marked with `<response clipped>`
* A null placeholder for a parameter unused by the selected command is treated as omitted. Required parameters still need values; omit `str_replace.new_str` rather than setting it to null when deleting a match

Notes for using the `str_replace` command:
* The `old_str` parameter should match EXACTLY one or more consecutive lines from the original file. Be mindful of whitespaces!
* If the `old_str` parameter is not unique in the file, the replacement will not be performed. Make sure to include enough context in `old_str` to make it unique
* The `new_str` parameter should contain the edited lines that should replace the `old_str`
```

### Whole-file write

`write` resolves the path, asks the single-slot `fs/write-intent` waterfall for an intent, and calls the backend without a prior stat. With `fs-observation-policy` mounted the intent is `createIfAbsent` for an unseen or confirmed-absent target and `replaceIfVersion` at the observed version for a seen one. The backend then takes a per-target lock, stats the target, checks the intent, creates missing parent directories, and writes through a private staging directory (`0o700`) and temp file (`0o600`) in the destination directory, syncs, and renames over the target. A `createIfAbsent` publish uses a hard link so a concurrent creator wins and this write fails. The existing POSIX mode is preserved. Content is written as supplied: no line-ending conversion, no BOM handling. The file's `before` text is read for the UI diff when both sides are under 10 MiB; the model does not see it.

### Matching

Exact literal match only. The backend reads the file inside the lock, rejects a NUL byte as binary, decodes as UTF-8, normalises CRLF to LF for matching, and normalises `old_string` and `new_string` the same way. The occurrence count decides: zero is an error, more than one without `replace_all` is an error. Replacement is `split` and `join`. The detected line-ending style (majority in the first 4096 characters) is restored on write-back. No fallback cascade, no whitespace-flexible retry, nothing reported about matching beyond success or the two errors.

### Multi-file patch

None. There is no patch grammar and no multi-file tool in the repository's shipped tool packages.

### Verification and mutation state

| Concern | Behaviour |
|---|---|
| Read-before-write | Enforced. `write` onto an existing file the session has not read fails; `edit` on an unread file fails. Both messages tell the model to read and retry |
| Stale-file check | Enforced. The version is `dev:ino:size:mtimeNs:ctimeNs` from the read; the backend re-stats inside the lock and rejects a changed file with `file changed since it was read` |
| Lock | Per-target FIFO promise chain keyed by `realpath`, held from stat through publish. Different keys run in parallel |
| Cross-process coordination | None. A `bash` command or another process is outside the observation map |
| Post-write checks | None. No formatter, no LSP, no syntax check |
| Change tracking | `fs/observed` is emitted after a successful mutation with the new version, so a follow-up edit needs no re-read |

The observation map is keyed by session object and lives in process memory; a session resumed in a new process starts with no observations, so the first mutation of any existing file needs a read.

### Output

| Tool | Model text |
|---|---|
| `write` | The read envelope shape with `Created file` or `Updated file` as the content |
| `edit` | `The file <path> has been updated successfully.` or, with `replace_all`, `The file <path> has been updated. All occurrences were successfully replaced.` |

Diffs go to presentation metadata for the UI, not to the model.

### Notable

- Under `workspace-write` a mutation outside the workspace root, `/tmp`, or the OS temp directory fails with the sandbox marker and an escalation hint. The model may retry once with `sandbox_permissions` and a `justification`; that retry raises the approval prompt.
- The sandbox fence is a path containment check in process, canonicalised immediately before the write; it is not a kernel boundary. The `bash` sandbox is the kernel boundary.
- `str_replace_editor` requires absolute paths, refuses `create` on an existing file, and clips long output with the `<response clipped>` note. It was not surveyed beyond its description and argument errors.
- No notebook editor, no undo, no checkpoint tool in this family.

### Working directory and environment

The working directory is the session workspace, or the resolved sandbox policy's workspace root when one applies, unless `workdir` is given. The child environment starts from the parent environment with two groups removed: every variable whose name matches `KEY`, `PASSWORD`, `SECRET`, or `TOKEN`, and every inherited `DSH_*` name. Over that the executor sets `NO_COLOR=1`, `TERM=dumb`, `PAGER=cat`, and `GIT_PAGER=cat`, then the managed set from `shell-env`: `DSH_HOME`, `DSH_SHELL=1`, `DSH_SESSION_ID`, and whatever registered contributors add, such as `DSH_WEB_URL` under the web host. The command runs as `bash -c <command>` through the sandbox runner. Login shell: None. Shell selection: `bash` on POSIX, `pwsh` on Windows, fixed by platform.

### Process lifecycle

| Aspect | Behaviour |
|---|---|
| Model | One child process per call. No persistent shell in the default set |
| Background | `run_in_background: true` returns `started background job <id>` at once; the job registers with `ctx.jobs` and is read with `job_output`, listed with `job_list`, stopped with `job_kill`. No timeout applies |
| stdin | Ignored |
| Timeout | 60000 ms default from the `bash-sandbox` row; `timeoutMs` up to 600000 ms; a larger request is clamped |
| Cancellation | The tool abort signal and the timeout share one deadline; `SIGTERM` then `SIGKILL` after a 3000 ms grace across the managed process range |
| Grandchildren | The subprocess service manages the spawned range and terminates it at kill and at composition teardown |
| Completion notice | A finished background job injects a user message into the owning agent by default (`completionDelivery: wakeup`) |

### Output limits

| Aspect | Behaviour |
|---|---|
| Collection | stdout and stderr are collected separately. Each keeps a 64000-byte in-memory tail; on first overflow the whole stream is appended to a spill file, up to 64 MiB per stream |
| Model-visible text | stdout, then `[stderr]` and the stderr text when present, then markers. Empty output is `(no output)` |
| Truncation text | `[output truncated; full output: <path>]` after the affected stream's tail, or `(unavailable)` when no spill file exists |
| Spill file | `dsh-subprocess-<pid>-<n>-<hex>-<label>.log` in a private `0700` directory under the OS temp directory; retained after the process |
| Result cap | `spill-policy` then caps the whole text result at 50000 bytes: the full text is saved under the session's spill directory and the model gets a head and tail preview followed by `(Omitted <n> bytes. Full formatted result stored at: <path>. Use read with offset/limit, or grep this path to search within it.)` |
| UI progress | Not surveyed |

### Sandbox

The `sandbox-local` provider wraps the `bash -c` argv. On Linux it probes `bwrap` first, then the Landlock launcher; on macOS `sandbox-exec` with an SBPL profile; on Windows an ACL restricted-token runner. When no runner works the command is refused with a `sandbox mode "<mode>" is requested but no sandbox backend is usable on this host` error; it never runs unconfined. The mode comes from `sandbox-policy`: `DSH_PERMISSION_MODE` or `workspace-write` by default, with `workspaceRoot` at `process.cwd()`; the web host can set a per-session mode from its permission presets `read-only`, `workspace-write`, and `danger-full-access`.

Under `workspace-write` the bwrap profile binds `/` read-only, mounts a fresh tmpfs at `/tmp`, binds the workspace root read-write, unshares the PID namespace, and dies with the parent. Landlock grants read on `/` and write on `/tmp`, `/dev/null`, and the workspace root. Seatbelt denies `file-write*` except the workspace root, `/tmp`, and the OS temp directory. Network: no namespace or rule restricts it in any profile. `danger-full-access` runs the plain local executor.

A denied write inside the sandbox is classified from the child's exit status and stderr against the runner's denial signatures, then reported as `[sandbox: file access denied under <mode> mode]` followed by the escalation hint marker.

### Approval

No per-command prompt exists in the default composition. No `tools/pre-execute` gate in the shipped rows returns `ask`. Approval is asked in two cases: a `sandbox_permissions` escalation on `bash`, `write`, or `edit`, and plugin management. The `approval` row's policy is `ask` unless `DSH_PERMISSION_MODE` is `danger-full-access`, in which case it is `never` and every ask resolves to rejected. An escalation must name a mode strictly wider than the call's current mode, and the grant applies to that one call. Outcomes: `allowed-once`, `rejected` (`the user rejected escalating this command to "<mode>"`), `cancelled`, or `unavailable` when no answerer is composed. Every outcome except `allowed-once` fails the call before the command runs.

### Notable

- A non-zero exit is a successful tool result with `[exit code: N]` as the last line. A signal death is `[killed by signal: <signal>]`. A timeout adds `[timed out after <n>ms]` before the exit marker.
- Abort is an error result: `Error: tool call aborted`.
- The `job_output` result ends with `[status: <status>]` or `[status: <status>, <detail>]`; an empty delta reads `(no new output)`. `wait: true` blocks up to 30000 ms by default, capped at 600000 ms.
- The `[sandbox: ...]` marker on `bash` is the same text the `write` and `edit` denials use, so the model learns one vocabulary.
- No PTY, no streaming to the model, no interactive input in the default set. The `minimal` preset's persistent `bash` runs a PTY through `terminal-bash` with a 300000 ms timeout; not surveyed beyond its description.
