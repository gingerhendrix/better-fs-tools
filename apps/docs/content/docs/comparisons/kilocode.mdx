Kilo Code is an open-source coding agent published by Kilo Org. The CLI, `@kilocode/cli`, is a fork of OpenCode that tracks upstream at `v1.18.13` and keeps the same seven dedicated file tools: `read`, `glob`, `grep`, `write`, `edit`, `apply_patch`, and `bash`. It adds a `background_process` tool for long-running commands, opt-in `semantic_search` and `repo_clone` tools, document conversion for `.docx`, `.xlsx`, `.ods`, and `.ipynb` inside `read`, encoding-preserving writes, a default shell permission of ask with a read-only allowlist, and an optional Bubblewrap or Seatbelt sandbox. This page is a delta against the [OpenCode](./opencode.mdx) page: where a section says the behaviour is the same, the OpenCode page holds the detail.

## Read

### Signature

```ts
read({ filePath: string, offset?: number, limit?: number })
```

Same as OpenCode: `filePath` is described as absolute and relative paths resolve against the instance directory; `offset` is one-based with zero mapped to one; `limit` defaults to 2000. Kilo clamps `limit` to at least 1 so a zero limit cannot loop.

### Description

`read`: 1158 characters, 1158 bytes, 15 lines, approximately 259 tokens. Byte-identical to the OpenCode string.

The string states the absolute-path rule, the 2000-line default, the one-indexed `offset`, the line prefix shape, directory listing with a trailing `/`, the 2000-character line cut, image and PDF attachments, and the parallel-read and no-tiny-slices habits. It does not mention the document conversion or the encoding fallback that Kilo adds.

**`read` (1158 characters)**

```text
Read a file or directory from the local filesystem. If the path does not exist, an error is returned.

Usage:
- The filePath parameter should be an absolute path.
- By default, this tool returns up to 2000 lines from the start of the file.
- The offset parameter is the line number to start from (1-indexed).
- To read later sections, call this tool again with a larger offset.
- Use the grep tool to find specific content in large files or files with long lines.
- If you are unsure of the correct file path, use the glob tool to look up filenames by glob pattern.
- Contents are returned with each line prefixed by its line number as `<line>: <content>`. For example, if a file has contents "foo\n", you will receive "1: foo\n". For directories, entries are returned one per line (without line numbers) with a trailing `/` for subdirectories.
- Any line longer than 2000 characters is truncated.
- Call this tool in parallel when you know there are multiple files you want to read.
- Avoid tiny repeated slices (30 line chunks). If you need more context, read a larger window.

```

### Path handling

Relative paths, Windows normalisation, no tilde, and no URL handling are the same as OpenCode. Two things differ.

A missing path returns `File not found: <path>` with no sibling suggestions. Kilo removed the parent-directory scan; the `miss` function resolves the parent with `realPath`, runs the external-directory check on it, asks the `read` permission for the requested path and the parent, then fails.

```text
File not found: <path>
```

Symlinks are resolved before authorization. For a file, `KiloReadObject.file` stats the requested path, resolves `realpath`, stats the resolved path, and fails when device and inode differ. The containment check and the `read` permission then run on the resolved target, so an in-worktree symlink to a file outside the project triggers the `external_directory` prompt. The file is opened with `O_RDONLY | O_NONBLOCK | O_NOFOLLOW`, stat-ed again on the handle, and re-resolved through `/proc/self/fd` on Linux; a change at any step fails with `File changed after authorization: <path>`. Directories are listed at their resolved path, which is also the path printed in the `path` tag. A configured git reference (`references` in config) that contains the target bypasses the external-directory check.

### Permissions

| Check | Behaviour |
|---|---|
| `read` permission | Asked per path as in OpenCode. Rules resolve as agent ruleset, then saved global rules, then session rules; a deny anywhere wins and a saved allow can lift an agent ask |
| `.env` hardening | A broad `read` allow (`*` permission or `*` pattern) is downgraded to ask for paths matching `*.env` or `*.env.*`; `*.env.example` stays allowed |
| Default agent | `build` allows everything, asks for `.env` reads, allows `.env.example`. Same shape as OpenCode with more pre-approved external directories: the truncation dir, `/tmp/kilo`, skill dirs, the global config dir, `~/.kilo`, `~/.kilocode`, and configured reference dirs |
| Ignore files | `.kilocodeignore` in the project and `~/.kilocode/.kilocodeignore` are converted to `read` and `edit` deny rules |
| Outside the project | `external_directory` ask on the parent directory glob, evaluated on the resolved path. A filesystem root no longer counts as containing everything |
| Device and special files | `Not a regular file: <path>` for FIFOs, sockets, and devices after `stat`; Windows named-pipe paths fail with `Named pipes cannot be read: <path>` |
| Denial text | `The user rejected permission to use this specific tool call.`; with feedback, `... with the following feedback: <feedback>`; for a rule, `The user has specified a rule which prevents you from using this specific tool call. Here are some of the relevant rules <json>` |
| Headless runs | A subagent ask under a plain `kilo run` session fails with the rule-denied text instead of waiting |

## Edit

### Signature

```ts
write({ filePath: string, content: string })
edit({ filePath: string, oldString: string, newString: string, replaceAll?: boolean })
apply_patch({ patchText: string })
```

Parameters and the patch envelope grammar are the same as OpenCode. Selection differs: Kilo hides only `edit` when patch mode is on and keeps `write` in the list. Patch mode is on when the model ID contains `gpt-` or the model family starts with `gpt`, unless the ID or family contains `gpt-4` or `oss` or the family is `gpt-image`; `KILO_E2E_LLM_URL` forces it on. All three ask under the shared `edit` permission.

### Description

`write`: 623 characters, 623 bytes, 9 lines, approximately 124 tokens. Byte-identical to OpenCode.
`edit`: 1369 characters, 1369 bytes, 11 lines, approximately 289 tokens. Byte-identical to OpenCode.
`apply_patch`: 1092 characters, 1098 bytes, 34 lines, approximately 263 tokens. Byte-identical to OpenCode.

The strings say what they say on the OpenCode page: `write` claims a read-first check the runtime does not enforce, `edit` quotes two failure strings the runtime does not throw, and `apply_patch` explains the envelope with an example.

### Whole-file write

The permission preview diff, the single ask, the direct platform write with parent creation, UTF-8 BOM preservation, formatters, LSP diagnostics, and file and watcher events are the same as OpenCode. Kilo adds four steps. `assertMutablePath` refuses `.kilo/agent-manager.json` and `.kilocode/agent-manager.json` before any check. The existing file is read with `EncodedIO.read`, which detects the encoding as under Read, and written back with `EncodedIO.write` in that encoding; a new file is UTF-8. When the sandbox is enabled the write runs inside a `batchMutations` block with a sandbox-aware `ensureDirectory`. After the write, `ConfigValidation.check` appends a `config_validation` block when the path is a Kilo config file: `kilo.json`, `kilo.jsonc`, `opencode.json`, `opencode.jsonc`, `AGENTS.md`, anything under `.kilo/` or `.kilocode/` except `plans/`, or anything under the global config directories.

```text
<config_validation>
Config file validated successfully.
</config_validation>
```

The block otherwise reads `ERROR: Config file at <path> is not valid JSON(C)` with the parse errors, `WARNING: Configuration is invalid at <path>` with one schema issue per line, or `ERROR: <path>` with a frontmatter message for agent and command Markdown files. Mode preservation: Not surveyed.

### Matching

Same as OpenCode: nine replacers in order, first candidate wins, the model is not told which stage matched, non-unique candidates skipped without `replaceAll`, the disproportionate-span guard, empty `oldString` creates a file, equal strings error. The only change is that the file is decoded with the detected encoding before matching and encoded back the same way.

### Multi-file patch

Same as OpenCode: every hunk parsed first, Update and Delete targets verified before one shared `edit` approval, file-by-file application with no rollback, Add overwrites. Kilo runs `assertMutablePath` per hunk, reads Update and Delete targets with `EncodedIO.read` and turns a read failure into `apply_patch verification failed: <message>`, records an encoding per change (adds are UTF-8), writes and moves with `EncodedIO.write`, and appends a `config_validation` block for every non-delete change.

### Verification and mutation state

| Concern | Behaviour |
|---|---|
| Read-before-write | Described, not enforced. Same as OpenCode |
| Stale-file check | None. Same as OpenCode |
| Lock | The `edit` semaphore keyed by realpath, as OpenCode. `write`, `apply_patch`, `bash` take no lock |
| Cross-process coordination | None |
| Post-write checks | LSP diagnostics as OpenCode, now filtered to the changed files in metadata; the `config_validation` block for config files |
| Sandbox | When enabled, `packages/core/src/fs-util.ts` wraps the platform filesystem with `decorateFileSystem` from `@kilocode/sandbox`, so every `FSUtil` mutation from these tools is confined to the profile's writable paths |
| Change tracking | File and watcher events and Git snapshots, as OpenCode |

### Output

| Tool | Model text |
|---|---|
| `write` | `Wrote file successfully.` then the LSP blocks as OpenCode, then the `config_validation` block when the path is a config file |
| `edit` | `Edit applied successfully.` then the same. The diff and a `filediff` object with additions and deletions go to metadata; the patch text is omitted from `filediff` when either side exceeds 500 000 characters |
| `apply_patch` | `Success. Updated the following files:` with one line per file, the LSP blocks, then one `config_validation` block per changed config file |

### Notable

- Same as OpenCode: the permission request carries a preview diff; no notebook editor, undo, or checkpoint tool in the CLI (the VS Code host registers `notebook_edit` behind `experimental.native_notebook_tools`); the `edit` description's quoted failure strings are not the runtime strings.
- Fork differences: `kilocode/tool/encoded-io.ts` (encoding-preserving read, write, and sync; sandbox mutation batching), `kilocode/config-validation.ts`, `kilocode/agent-manager/protection.ts`, `tool/diagnostics.ts` (diagnostics filtered to changed files), `buildFileDiff` in `edit.ts`, and the `write` visibility change in `tool/registry.ts`. `packages/core/src/patch.ts` is identical to upstream and not used by the CLI.

## Shell

### Signature

```ts
bash({ command: string, timeout?: number, workdir?: string, description?: string })
```

`timeout` and `workdir` are as OpenCode: milliseconds, default 120000, negative rejected. `description` is new and optional; its parameter text begins `Recommended: a clear, concise description of what this command does in 5-10 words.` and gives four input and output examples. When `KILO_COMMAND_TIMEOUT_MAX_MS` is set, `timeout` is clamped to it. The tool ID and permission key are `bash` on every shell.

### Description

`bash`: 5070 characters, 5070 bytes, 63 lines, approximately 1159 tokens. Rendered for `os=linux`, `shell=bash`, the default 2000-line and 51200-byte output limits, the 120000 ms timeout, and `/tmp/kilo` as the temporary directory (`Global.Path.tmp` is `os.tmpdir()/kilo`). PowerShell and `cmd.exe` profiles render different text.
`background_process`: 2229 characters, 2229 bytes, 29 lines, approximately 488 tokens.

The `bash` string differs from the OpenCode string in five places: the intro says `Executes a given command` instead of `Executes a given bash command`; the temporary directory is `/tmp/kilo`; a usage note asks for a 5-10 word description; `Avoid using Bash with` becomes `Avoid using the shell with`; and the Git section opens with a bullet about the sandbox and one-shot confirmation for mutating Git commands. Everything else is the same text. `background_process` tells the model to use the tool only for processes that must outlive the call, never for waits, lists the six actions, the three lifetimes, and the two readiness probes.

**`bash` (5070 characters)**


**`background_process` (2229 characters)**

```text
Run and manage long-running background processes.

Use this tool only for processes that must keep running independently after this tool call returns, such as development servers, file watchers, local services, and test watchers (`npm run dev`, `next dev`, `vite`, or `bun --watch`).

This tool cannot wait: `start` returns immediately and never blocks your turn. Do not start `sleep`, timers, cooldowns, delays, or polling loops with this tool. To wait a fixed time before your next action, run the wait as a normal blocking shell command and set its `timeout` higher than the wait.

Do not use the shell tool with `&`, `nohup`, `disown`, `setsid`, `Start-Process`, or similar backgrounding patterns. Processes started with this tool are tracked and shown in the CLI sidebar.

Actions:
- `start`: start a new background process. Include `command`, optional `workdir`, optional `description`, optional `ready` detection, and at most one lifetime option.
- `list`: list background processes for this session.
- `status`: inspect one process by `id`.
- `logs`: return the retained tail output for one process.
- `stop`: terminate one process and its child process tree.
- `restart`: stop and restart one process with its original command and lifetime.

Lifetime options for `start`:
- By default, the process stops when its session ends, the user switches session groups, or Kilo exits.
- Set `inherit: true` only from a subagent when the process should transfer to the immediate parent session after the subagent ends. It then follows the parent session lifetime.
- Set `persistent: true` when the process must survive both session closure and Kilo shutdown. Persistent processes are visible and manageable from every session, including after Kilo starts again.
- `inherit` and `persistent` cannot be combined.

Only include `id` for `status`, `logs`, `stop`, and `restart`. Do not invent or pass an `id` when starting a process.

Readiness:
- Use `ready.pattern` when the process prints a recognizable line like `ready`, `Local:`, or `started server`.
- Use `ready.port` when a local server should accept TCP connections on a known port.
```

### Output limits

Same as OpenCode: combined stdout and stderr, rolling in-memory tail, spill to a `tool_*` file after 2000 lines or 50 KiB, `...output truncated...` then `Full output saved to: <file>`, `(no output)`, `tool_output.max_lines` and `tool_output.max_bytes` overrides, seven-day cleanup by file mtime. `background_process` `logs` returns the retained tail or `(no output)`.

### Sandbox

Off by default. `sandbox.enabled` defaults to false and `sandbox.network` to `deny`. When enabled, every tool call in the session runs under `SandboxPolicy.executeTool`: Bubblewrap on Linux, Seatbelt on macOS, unavailable on Windows. The profile allows writes to the worktree and instance directory, the Kilo data, cache, config, state, tmp, bin, log, and repos directories, and `sandbox.writable_paths`; denies writes to the sandbox store, the sandbox preference file, and the global config directory; denies any path named `.git`; and strips the `KILO_*` credential variables. Network is denied, proxied to `sandbox.allowed_hosts`, or allowed. A project config can tighten the global sandbox and cannot loosen it. Mutating Git commands need a separate `sandbox_escalation` permission that cannot be saved as always and must be answered by an interactive client; when approved, that single command runs unrestricted. Without the sandbox there is no isolation, as OpenCode.

### Approval

The Tree-sitter parse, per-command patterns, arity-based always patterns, and the file-command path scan that raises `external_directory` before `bash` are the same as OpenCode. Kilo changes what the patterns look like and what the defaults are.

- Patterns are rendered from the parse tree with operator characters masked as `_` where the parser proves them inert: inside quotes, ANSI-C strings, heredoc bodies, `/dev/null` redirects, and fd duplication. A quoted `|` no longer matches a `*|*` deny rule.
- A command the grammar fails to parse still yields at least one pattern: the text of each parser error node, or the raw command. `Failed to parse command` remains for a null parse tree.
- Plain `cat` and `get-content` without redirects are tagged as read access; an `external_directory` request tagged `read` is exempt from the config-path protection below.
- The default `bash` ruleset for every built-in agent is `*` ask, with allow for `cat`, `head`, `tail`, `less`, `ls`, `tree`, `pwd`, `echo`, `wc`, `which`, `type`, `file`, `diff`, `du`, `df`, `date`, `uname`, `whoami`, `printenv`, `man`, `grep`, `rg`, `ag`, `sort`, `uniq`, `cut`, `tr`, `jq`, `touch`, `mkdir`, `cp`, `mv`, `tsc`, `tsgo`, `tar`, `unzip`, `gzip`, and `gunzip`, each as `<cmd> *`. OpenCode's `build` agent allows every command. `hardenPlan` and `hardenExplore` give the `plan` and `explore` agents a read-only ruleset that denies `*` and most `git` and allows listed read-only `git` and `gh` subcommands.
- "Always" approvals are persisted to the global config `permission` block. Requests that touch Kilo config paths cannot be saved as always and the UI is told through `disableAlways` metadata; global skill directories are the exception.
- Rejecting one request rejects the session's pending requests. Requests marked `skillShell` or `sandboxEscalation` need an interactive reply and ignore machine approvals.

### Notable

`glob` is as OpenCode with three changes: an absolute pattern such as `/home/me/.config/kilo/command/*.md` is split into a search directory and a relative pattern; truncation comes from the ripgrep result rather than a count of exactly 100; and `(Some discovered files could not be read.)` is appended after a partial ripgrep exit. A search over two minutes fails with `Glob search timed out after 2 minutes. Narrow the search path or pattern.`. The abort signal now reaches ripgrep. `grep` keeps the `Found <n> matches` header and the `<path>:` grouping. With `context` zero each row is `  Line <n>: <text>` as OpenCode; with `context` above zero rows are `  [match] Line <n>: <text>` and `  [context] Line <n>: <text>`, and the count excludes context rows. When any line was cut at 2000 characters the output ends with `Some matching or context lines were truncated. Use read for full lines.`; a partial ripgrep exit adds `(Some paths were inaccessible.)`. A file target is passed to ripgrep as a single file. A target that is neither a file nor a directory returns `No files found`. `pattern is required` and the empty-result text are unchanged.

`semantic_search` asks the `semantic_search` permission with the query, then returns ranked snippets with file path and line range from the Kilo indexing service. `repo_clone` asks the `repo_clone` permission, clones or refreshes into the Kilo data directory, and returns `Repository ready: <label>`, `Status: cached|cloned|refreshed`, `Local path: <path>`, and optional `Branch:` and `HEAD:` lines.
