Qwen Code is Alibaba's open-source terminal coding agent. It began as a fork of Gemini CLI `v0.8.2` and stopped syncing with upstream at Qwen Code `v0.1`. Its model-facing file family is eight dedicated tools: `read_file`, `write_file`, `edit`, `notebook_edit`, `glob`, `grep_search`, `run_shell_command`, and `monitor`, with `list_directory` available as an opt-in. Two things set it apart from its parent. A session file-read cache turns read-before-write into an enforced rule with an mtime and size fingerprint, and the `read_file` description is rendered from the input modalities of the active model, so the same tool ships four different strings.

## Read

### Signature

```ts
read_file({ file_path: string, offset?: integer, limit?: integer, pages?: string })
```

`file_path` must be absolute; a relative path fails validation. `offset` is zero-based and `limit` is a count, so `offset: 10, limit: 20` returns lines 11 to 30 in the one-based numbering the response uses. With neither, the first 1000 lines are returned (`truncateToolOutputLines`). `pages` selects PDF pages, one-based, at most 20 per call, and open-ended ranges are rejected. `offset`, `limit`, and `pages` are rejected for `.ipynb` files.

### Description

`read_file`, no audio or video input: 1317 characters, 1317 bytes, 1 line, approximately 293 tokens.
`read_file`, video input: 1791 characters, 1795 bytes, 1 line, approximately 395 tokens. This is the variant the default `coder-model` receives.
`read_file`, audio input: 1784 characters, 1788 bytes, 1 line, approximately 394 tokens.
`read_file`, audio and video input: 1877 characters, 1881 bytes, 1 line, approximately 425 tokens.

`buildReadFileDescription(modalities)` in `read-file.ts` composes the string from a fixed preamble, a modality-dependent middle, and a fixed trailer. The preamble states the absolute-path rule with a worked example, says large files are truncated, and names `offset` and `limit` for continuation. The trailer covers line ranges, the `pages` parameter and its 20-page cap, PDF fallbacks and the vision bridge, and notebook reads. The middle lists the media formats; when audio or video is on it adds a sentence telling the model the media is delivered for direct perception and to re-read a clip after cutting it. No variant states the default window, the offset base, or the line prefix. The modalities come from `defaultModalities(model)` in `core/modalityDefaults.ts`, a name-pattern table where unknown models are text-only, unless a `modelProviders` entry sets them. The `schema` getter recomputes the string on every declaration build, so a `/model` switch changes it mid-session. Three of the four strings contain U+2014, which is why their byte counts exceed their character counts.

### Path handling

Validation trims the path and, outside Windows, removes backslash escapes before shell metacharacters, so `my\ file.txt` becomes `my file.txt`. The path must be absolute; otherwise `File path must be absolute, but was relative: <path>. You must provide an absolute path.` is returned as a validation error. Execution calls `path.resolve` and reads through `fs.stat`, so symlinks are followed. No tilde expansion and no URL handling.

Near-miss recovery: None. A missing file returns:

```text
File not found: <path>
```

The message travels in the function response `error` field. The tool's `llmContent` for that case, `Could not read file because no file was found at the specified path.`, is dropped by the scheduler when an error is set; see Errors. This matches the Gemini CLI page.

### Permissions

| Check | Behaviour |
|---|---|
| Default permission | `allow` when the real path sits under a workspace directory, the project temp directory, the project `subagents` directory, the global temp directory, a user skills or extensions directory, the plans directory, the user workflows directory, the workflow runs directory, or a managed auto-memory root. Otherwise `ask`, which raises a confirmation dialog. The candidate is canonicalised with `realpathNearestExisting` before the check, so a symlink planted inside the workspace that points outside is treated by its target |
| Permission rules | `Read(<path-glob>)` rules from settings can override with `allow`, `ask`, or `deny`. A deny returns `This "read_file" invocation was denied by permission rules. Matching deny rule: "<rule>". Other uses of this tool are still permitted.` |
| Approval modes | `yolo` skips the dialog. `plan` allows reads. `auto` runs an LLM classifier for calls that are not already allowed |
| Ignore rules | `.qwenignore`, `.agentignore`, and `.aiignore` patterns are checked at validation: `File path '<path>' is ignored by <ignore file> pattern(s).` `.gitignore` does not apply to `read_file` |
| Device and special files | `stats.isFile()` must hold. FIFOs, sockets, and devices return `Not a regular file: <path>` |
| Blocked segments | None. No `.git`, `.env`, or `node_modules` refusal in the read path |
| Denial text for invalid parameters | `Error: Invalid parameters provided. Reason: <message>` |

### Binary and conversion

| Aspect | Behaviour |
|---|---|
| Detection | `.ts`, `.mts`, `.cts`, `.tsx` are text; `.svg` and `.ipynb` have their own types. Then a `mime` lookup: `image/*` is sniffed over 8 KiB of magic bytes for PNG, JPEG, WebP, and GIF; `audio/*`, `video/*`, and `application/pdf` map directly; declared text MIME types are trusted. Then the `BINARY_EXTENSIONS` list, a curated text extension list, a text basename list (`Dockerfile`, `Makefile`, lockfiles), and finally a 4 KiB sample: a NUL byte or more than 30 percent non-printable bytes means binary; a BOM means text |
| Refusal | `Cannot display content of binary file: <rel>` returned as success text with no error field |
| Notebooks | Rendered as `Jupyter Notebook (<language>, <n> cells)` followed by one block per cell with its id and outputs. Output is capped at 100 000 characters with a `... [<n> remaining cells truncated ...]` line; a truncated notebook read does not unlock `notebook_edit` |
| SVG | Read as text up to 1 MiB; `Cannot display content of SVG file larger than 1MB: <rel>` above that |
| Images | PNG, JPEG, and WebP are decoded with `sharp`, oriented, scaled to at most 1568 pixels on the long edge, and returned as a JPEG `inlineData` part preceded by `Image overview: <w>x<h>; oriented source: <w>x<h>. If details are too small, use tool_search for "zoom image", then call zoom_image with coordinates normalized from 0 to 1000.` GIF is validated and forwarded as-is. Other image MIME types are omitted with `Image format <mime> (<rel>) cannot be safely sent to the model, so its data was omitted from the request. ...`. Source files over 100 MB are refused. A model without image input gets `[Unsupported image file: "<name>". This model does not support image input. ...]` as success text |
| PDF | With `pdf` modality and no `pages`, the whole file as base64 `inlineData` under 10 MB. Otherwise `pdftotext` extraction, capped at 12 000 estimated tokens; full-text extraction refuses files over 100 MB and page-range extraction over 512 MB. On overflow or failure a vision-capable model gets pages rendered to images (at most 20); a text-only model with a configured vision bridge gets at most four pages transcribed; otherwise guidance to narrow `pages` is returned as an error |
| Audio and video | Base64 `inlineData` when the model has the modality and the encoded size is under 10 MB (9.9 MB threshold); otherwise `[Unsupported <audio\|video> file: "<name>". ...]` as success text. With the opt-in omni pipeline, media is uploaded instead of inlined |
| Encoding | BOM-aware for UTF-8, UTF-16 LE and BE, and UTF-32 LE and BE; a file without a BOM that fails UTF-8 validation is detected with `chardet` and decoded with `iconv-lite`; the detected encoding and BOM are carried to later writes |

### Limits

| Limit | Value | Message |
|---|---|---|
| Default window | 1000 lines (`truncateToolOutputLines`; `0` or less removes the cap) | |
| Ceiling | The model's `limit`. No upper bound on the request | |
| Character budget | 25 000 characters of selected lines (`truncateToolOutputThreshold`). The line that crosses the budget is cut with `... [truncated]` and the read stops there | The banner below reports the lines shown |
| Byte budget | The read stops at `max(25000, threshold * 4)` bytes, 100 000 by default; `... [truncated]` is appended | |
| Long line | No per-line cap. Only the character budget cuts a line | |
| Whole-file size | None for text. Files of 10 MiB and above are streamed with a bounded scan and report the total as `at least <n>` | |
| Offset past end | Not an error. The banner reports `Showing lines <offset+1>-<offset+1> of <total> total lines.` over an empty body | |
| Line handling | Split on `\n`; every returned line has trailing whitespace removed | |

### Output

```text
Showing lines 1-1000 of 5000 total lines.

---

import { x } from "./x"
export const y = x
```

The example is reconstructed from the format code. A read that returns the whole file has no banner: the content is bare, with no line numbers and no end marker. The banner appears when the read stopped before the end, when `offset` was above zero, or when the character or byte budget cut a line.

| Aspect | Behaviour |
|---|---|
| Prefix before content | None on a full read. `Showing lines <a>-<b> of <total> total lines.`, a blank line, `---`, and a blank line when truncated or offset |
| Line prefix | None. Lines are bare |
| End marker | None |
| Truncation notice | The banner above, before the content. A `... [truncated]` marker ends the content when the character or byte budget cut it |
| Error transport | Function response `{ error: "<message>" }` with no `output` field; the success response is `{ output: "<text>" }` or media parts |

### Notable

- Repeat-read guard: a full read of a file whose inode, mtime, and size match the last full text read in this session, with no write since and the earlier result still in history, returns `[File <rel> unchanged since last read in this session — the full content was provided earlier in this conversation. If you cannot retrieve that prior content (e.g. after context compaction) or you suspect the file was modified outside the read/edit tools (shell command, MCP tool, another process), re-read with explicit offset/limit to fetch current content.]` instead of content. `fileReadCacheDisabled: true` turns this off.
- Every text read records the file's `dev:ino` key, mtime, and size in the session `FileReadCache`. `edit`, `write_file`, and `notebook_edit` consult it; see Edit.
- An empty file returns `(read_file completed with no output)`, inserted by the scheduler's truncation pass.
- Auto-memory files under the managed memory roots get a freshness reminder prepended and never take the repeat-read fast path.
- After the content, the scheduler can append a `system-reminder` envelope with conditional rules or activated skills matched by the path, so the result can carry text that is not in the file.
- `read_file` is exempt from the scheduler's per-tool character truncation (`maxOutputChars` is `Infinity`). The per-message batch budget of 200 000 characters across all tool results still applies; the largest results are offloaded to disk with a `persisted-output` stub.

## Edit

### Signature

```ts
write_file({ file_path: string, content: string, record_as_artifact?: boolean })
edit({ file_path: string, old_string: string, new_string: string, replace_all?: boolean })
notebook_edit({ notebook_path: string, cell_id?: string, new_source?: string, cell_type?: "code" | "markdown", edit_mode?: "replace" | "insert" | "delete" })
```

All three require absolute paths. `replace_all` is a boolean defaulting to `false`. `record_as_artifact` defaults to `true` for artifact-like extensions and only matters when artifact recording is enabled. `notebook_edit` defaults `edit_mode` to `replace`; `cell_id` is required for `replace` and `delete`, and `new_source` for `replace` and `insert`. The legacy name `replace` resolves to `edit`. There is no delete tool and no multi-file patch tool. All three are `Kind.Edit`, which the scheduler treats as mutators.

### Description

`write_file`: 1180 characters, 1184 bytes, 5 lines, approximately 239 tokens.
`edit`: 1518 characters, 1518 bytes, 11 lines, approximately 309 tokens.
`notebook_edit`: 260 characters, 260 bytes, 1 line, approximately 57 tokens.

`write_file` tells the model that a request to create a file does not prove the path is new, that it MUST call `read_file` first unless the target's absence or contents are already established, that blind overwrites are rejected under prior-read enforcement, how to build the absolute path, and that HTML, PDF, image, notebook, and office files are registered as session artifacts unless `record_as_artifact=false` or written under `.qwen/tmp/`. `edit` carries the numbered rules from the Gemini CLI default-legacy `replace` string with the `instruction` rule removed and the `allow_multiple` flag renamed `replace_all`; it keeps the six-space indentation on its second paragraph. `notebook_edit` says to use it instead of `edit` or `write_file` for cells and to take cell ids from `read_file` output. The `write_file` string contains one U+2014.

### Whole-file write

Validation rejects a relative path, a directory target (`Path is a directory, not a file: <path>`), and content that would place a secret in a team memory file. Before the confirmation diff and again in `execute`, the tool runs `checkPriorRead` against the session cache: once before reading the current file, once after reading it, and once more just before the write, each time re-stating the file. Any rejection returns the enforcement message as an error and leaves the file untouched. Parent directories are created with `mkdirSync({ recursive: true })` only after the last check passes.

The write goes through `StandardFileSystemService.writeTextFile`, which prepares the bytes and calls `atomicWriteFile`: a temporary file in the same directory, `fsync`, then `rename`, with three retries on `EPERM` or `EACCES`. The existing file's permission bits are preserved. BOM: an existing UTF-8 BOM is re-emitted; a new file gets one when `defaultFileEncoding` is `utf-8-bom` or when the platform heuristic asks for it (`.ps1` on Windows). Encoding: a file detected as GBK, Shift_JIS, UTF-16, or another non-UTF-8 encoding is written back in that encoding through `iconv-lite`. Line endings: when the existing file used CRLF, every line ending in the new content is converted to CRLF; on Windows a small extension list forces CRLF for new files. After the write the tool re-stats the file and records the write in the cache so the next read bypasses the repeat-read guard. A file history snapshot is taken before the write. Commit attribution records the AI contribution. No post-write verification of the bytes.

### Matching

`edit` reads the file, normalises CRLF to LF, and asks `normalizeEditStrings` for the canonical slice. The cascade is: a literal `indexOf`; then `indexOf` after mapping hyphen, dash, curly quote, and Unicode space variants to ASCII in both strings; then a line-based search whose passes compare lines exactly, then with trailing whitespace trimmed, then with the Unicode mapping plus trailing trim. Leading whitespace is never relaxed. The first pass that finds the lines returns the exact bytes from disk, and those bytes become `old_string`, so the replacement always operates on file content. `new_string` is kept as supplied, except that a trailing newline is dropped when the matched slice dropped one. The model is not told which pass matched. When `new_string` is empty and the file holds `old_string` followed by a newline, the newline is consumed so the deletion leaves no blank line.

Occurrences are then counted on the canonical `old_string`. Without `replace_all` the count must be exactly one. An empty `old_string` creates the file when it does not exist and fails when it does. Equal strings, or a replacement that leaves the content unchanged, fail with a no-change error. The replacement itself uses `safeLiteralReplace`, which handles `$` sequences literally. Validation completes before any write. There is no LLM correction path.

### Sandbox

Optional and off by default. `--sandbox`, `QWEN_SANDBOX`, or the `tools.sandbox` setting select a whole-process sandbox that relaunches the CLI inside `docker`, `podman`, `sandbox-exec` on macOS, or `bwrap` on Linux, after a probe confirms the runtime works. Without it, `run_shell_command` and `monitor` run as the user's process with no seccomp profile, no network policy, and no filesystem scope beyond the `directory` validation. ### Approval

Permission is decided in layers. The tool's default (`L3`) is `ask` when the command contains substitution syntax (`$()`, backticks, `<()`, `>()`), `allow` when a Tree-sitter parse classifies every segment as read-only in the target directory, and `ask` otherwise. Permission rules (`L4`) of the form `Bash(<prefix> *)` can allow, ask, or deny; a deny returns `This "run_shell_command" invocation was denied by permission rules. Matching deny rule: "<rule>".
