Claude Code is Anthropic's terminal coding agent, shipped as a proprietary native binary with public TypeScript declarations. Its model-facing file family is dedicated tools: `Read`, `Write`, `Edit`, `NotebookEdit`, `Glob`, `Grep`, and `Bash`, with no directory-listing tool. The read tool counts tokens with the provider tokenizer and paginates a whole-file read that passes the cap, and a conversation-local read ledger gates `Edit` and `Write`. There is no public source, so this page rests on template strings extracted from the installed binary, the package declarations, a live session, and vendor documentation.

There is no list, stat, delete, or mkdir tool; the model uses `Bash`. A bare permission deny such as `Bash` removes the tool from model context; a scoped deny keeps it visible and blocks matching calls. The SDK `Options.tools` list and `toolAliases` can change the set or redirect a built-in name to a host MCP tool. The binary holds several description variants per tool, chosen by model and a lean-prompt flag; the strings on this page are the variants active in the observed `opus` session. MCP and user-defined tools are outside this table.

## Read

### Signature

```ts
Read({ file_path: string, offset?: number, limit?: number, pages?: string })
```

`file_path` is described as absolute; the binary resolves a relative path against the working directory. `offset` is one-based and defaults to `1`. `limit` is a line count. `pages` selects PDF pages as `"1-5"`, `"3"`, or `"10-20"`, at most 20 pages per call, and is required for PDFs over ten pages. The declaration is `FileReadInput` in `sdk-tools.d.ts` at `2.1.241`.

### Description

`Read`: 790 characters, 794 bytes, 9 lines, approximately 191 tokens.

**`Read` (790 characters)**

```text
Reads a file from the local filesystem.

- `file_path` must be an absolute path.
- Reads up to 2000 lines by default.
- When you already know which part of the file you need, only read that part. This can be important for larger files.
- Results are returned using cat -n format, with line numbers starting at 1
- Reads images (PNG, JPG, …) and presents them visually. Reads PDFs via the `pages` parameter (e.g. "1-5", max 20 pages/request; required for PDFs over 10 pages). Reads Jupyter notebooks (.ipynb) as cells with outputs.
- Reading a directory, a missing file, or an empty file returns an error or system reminder rather than content.
- Do NOT re-read a file you just edited to verify — Edit/Write would have errored if the change failed, and the harness tracks file state for you.
```

### Path handling

The path is resolved against the working directory. On `ENOENT` the tool retries once with the macOS screenshot variant: a basename matching `<name> AM.png` or `<name> PM.png` has the space before `AM` or `PM` swapped between U+0020 and U+202F. If the retry also fails, two suggesters run. The first returns a sibling whose name without extension equals the requested stem, as a bare name. The second checks whether the path sits under the parent of the working directory but not under the working directory itself, joins the same relative tail onto the working directory, and suggests that absolute path when it exists. The re-anchor suggestion wins over the same-stem one. The suggestion is appended to the error. The file is never read from a suggestion.

```text
File does not exist. Note: your current working directory is <cwd>. Did you mean <suggestion>?
```

Without a suggester match the message ends after the working directory. There is no tilde expansion and no URL handling in the read path.

Symlinks: permission checks evaluate the link path and the resolved target; an allow needs both to match and a deny on either blocks. The binary stashes an identity for the path at permission time and checks it again at read time on macOS.

### Notable

- Repeat-read guard: the same path, `offset`, and `limit` with an unchanged mtime returns `File unchanged since last read. The content from the earlier Read tool_result in this conversation is still current — refer to that instead of re-reading.` instead of content. The binary also holds a shorter `Wasted call — file unchanged since your last Read. Refer to that earlier tool_result instead.` and a `system-reminder` variant for a file whose content was already seeded into context.
- Empty file: `<system-reminder>Warning: the file exists but the contents are empty.</system-reminder>`.
- The read is recorded in the conversation-local ledger with its mtime, `offset`, `limit`, a content hash, and a partial-view flag. `Edit` and `Write` consult this ledger.
- The path is pushed into nested memory triggers so `CLAUDE.md` files in the tree can attach in a later message. A path that belongs to a registered background task is filtered through the task output formatter.
- The read accepts an abort signal.
- No redaction.

## Edit

### Signature

```ts
Write({ file_path: string, content: string })
Edit({ file_path: string, old_string: string, new_string: string, replace_all?: boolean })
NotebookEdit({ notebook_path: string, new_source: string, cell_id?: string, cell_type?: "code" | "markdown", edit_mode?: "replace" | "insert" | "delete" })
```

`replace_all` defaults to false. `old_string` and `new_string` must differ. `NotebookEdit` defaults `edit_mode` to `replace`; `insert` requires `cell_type` and inserts after `cell_id`, or at the start when no ID is given. There is no patch tool. The declarations are `FileWriteInput`, `FileEditInput`, and `NotebookEditInput` in `sdk-tools.d.ts` at `2.1.241`.

### Description

`Write`: 240 characters, 240 bytes, 3 lines, approximately 50 tokens.
`Edit`: 360 characters, 362 bytes, 5 lines, approximately 76 tokens.
`NotebookEdit`: Not surveyed. The string was not extracted in the 2026-09-16 session.

**`Write` (240 characters)**

```text
Writes a file to the local filesystem, overwriting if one exists.

When to use: creating a new file, or fully replacing one you've already Read. Overwriting an existing file you haven't Read will fail. For partial changes, use Edit instead.
```

**`Edit` (360 characters)**

```text
Performs exact string replacement in a file.

- You must Read the file in this conversation before editing, or the call will fail.
- `old_string` must match the file exactly, including indentation, and be unique — the edit fails otherwise. Strip the Read line prefix (line number + tab) before matching.
- `replace_all: true` replaces every occurrence instead.
```

### Whole-file write

`Write` creates or overwrites the whole file. It does not append or merge. The result records `create` or `update`, the original content or `null`, a line-based `structuredPatch`, an optional Git diff summary, and `userModified` when the user changed the proposed content in the permission dialog.

From the `2.1.273` binary: the writer detects the file's encoding and line-ending style, restores CRLF when the file used it, writes with the detected encoding, then stats the file and compares the size on disk with the bytes written. A mismatch fails with `Write verification failed: <path> is <n> bytes on disk, expected <m>. The filesystem may have silently truncated the write (network drive / cloud sync).` The mtime after the write is stored in the read ledger.

Atomic replace through a temporary file and rename: Unverified. Parent directory creation: Not surveyed. Mode, owner, and timestamp preservation: Not surveyed. `fsync`: Not surveyed.

### Matching

The documentation at `2.1.241` describes literal replacement with no regex and no fuzzy matching, one occurrence unless `replace_all` is true. The `2.1.273` binary shows a cascade in front of that rule. Exact `includes` runs first. When it misses, the file and `old_string` are compared with curly quotes folded to straight ones, U+2018 and U+2019 to `'` and U+201C and U+201D to `"`; on a hit the file's own substring becomes the string to replace and `new_string` receives the same quote style. When `old_string` holds `\uXXXX` escapes, the decoded form is tried. When `old_string` holds non-ASCII characters, a regex that accepts either spelling is tried. The result is not labelled with the stage that matched.

Occurrences are counted over the normalised file. More than one occurrence without `replace_all` is an error. An empty `old_string` creates a new file and errors when the target already holds non-whitespace content. The file is read with a UTF-16LE check on the BOM, a UTF-8 BOM strip, and CRLF normalisation before matching.

### Multi-file patch

None. `Edit` covers one file per call. `NotebookEdit` covers one cell. There is no patch grammar.

### Verification and mutation state

| Concern | Behaviour |
|---|---|
| Read-before-write | Enforced by the conversation-local ledger. Older model families always need the read; newer models can edit or overwrite an unread file when `Read` is available and the read would not prompt. A partial read never counts. A single-file `cat`, `nl`, `bat`, `batcat`, `head`, `tail`, `sed -n 'X,Yp'`, `grep`, `egrep`, `fgrep`, or `rg` through `Bash` counts; pipes and redirects do not |
| Not-read text | `File has not been read yet. Read it first before writing to it.` |
| Stale-file check | The ledger holds the mtime and a content hash. When the mtime moved and the content differs, `Write` and `NotebookEdit` return `File has been modified since read, either by the user or by a linter. Read it again before attempting to write it.`; `Edit` returns `File content has changed since it was last read. This commonly happens when a linter or formatter run via Bash rewrites the file. Call Read on this file to refresh, then retry the edit.`. `Edit` can proceed when `old_string` still matches exactly and unambiguously and a fresh read would not prompt; the result then notes the other changes |
| Bash writes | A `Bash` command matching write markers bumps the ledger and adds `staleReadFileStateHint` to the result |
| Lock | None published. No same-path serialisation, compare-and-swap, or atomic check-and-write is promised. Parallel tool batches are supported |
| Size and mode guards | `Edit` refuses a file over 1 GiB: `File is too large to edit (<size>). Maximum editable file size is <max>.` With `CLAUDE_CODE_PERFORCE_MODE` a file without the write bit is refused with a message naming `p4 edit` |
| Post-write checks | None published |
| Change tracking | Direct editing tools snapshot files before prompts; the most recent 100 session checkpoints are kept. Rewind does not track `Bash` mutations, most subagent changes, or external edits, and skips symlinked and hard-linked files |

## Shell

### Signature

```ts
Bash({ command: string, timeout?: number, description?: string, run_in_background?: boolean, dangerouslyDisableSandbox?: boolean })
```

`timeout` is in milliseconds; the description says default 120000 and maximum 600000, and `BASH_DEFAULT_TIMEOUT_MS` and `BASH_MAX_TIMEOUT_MS` move both. `description` is shown in permission prompts. `run_in_background` starts a task and returns. `dangerouslyDisableSandbox` requests a run outside the sandbox and goes through normal permission handling. The declaration is `BashInput` in `sdk-tools.d.ts` at `2.1.241`.

### Description

`Bash`: 1331 characters, 1333 bytes, 13 lines, approximately 309 tokens.
`PowerShell`, `TaskOutput`, `TaskStop`: Not surveyed. The strings were not extracted in the 2026-09-16 session.

**`Bash` (1331 characters)**

```text
Executes a bash command and returns its output.

- Working directory persists between calls, but prefer absolute paths — `cd` in a compound command can trigger a permission prompt. Shell state (env vars, functions) does not persist; the shell is initialized from the user's profile.
- IMPORTANT: Avoid using this tool to run `find`, `grep`, `cat`, `head`, `tail`, `sed`, `awk`, or `echo` commands, unless explicitly instructed or after you have verified that a dedicated tool cannot accomplish your task. Instead, use the appropriate dedicated tool as this will provide a much better experience for the user.
- Command output is displayed to you, not reliably to the user.
- `timeout` is in milliseconds: default 120000, max 600000.
- `run_in_background` runs the command detached: it keeps running across turns and re-invokes you when it exits. No `&` needed. Foreground `sleep` is blocked; use Monitor with an until-loop to wait on a condition.

# Git
- Interactive flags (`-i`, e.g. `git rebase -i`, `git add -i`) are not supported in this environment.
- Use the `gh` CLI for GitHub operations (PRs, issues, API).
- Commit or push only when the user asks. If on the default branch, branch first.
- End git commit messages and PR bodies with the attribution lines given in the conversation's system-reminder, when one is present.
```

### Working directory and environment

Each call starts a separate process. A `cd` in the main session persists for later calls only inside the project or an added directory; a disallowed destination resets to the project. Subagent directory changes do not persist. Environment variable assignments do not persist; Claude Code captures shell aliases, functions, and options at session start and reapplies them, and `CLAUDE_ENV_FILE` names a script to source. The description says the shell is initialised from the user's profile. Shell binary selection and login-shell flags: Not surveyed.

### Process lifecycle

| Aspect | Behaviour |
|---|---|
| Model | One process per call. Foreground, timeout transition, background task, and interruption are distinct states in the result |
| Timeout | A command that reaches its timeout is moved to the background: `Command did not complete within its <n>s timeout and was moved to the background (ID: <id>). Output is being written to: <path>.` A command starting with `sleep`, a command containing `git`, or a compound command that cannot be parsed is stopped instead: `Command timed out after <duration>` |
| Background | `run_in_background: true` returns `Command running in background with ID: <id>. Output is being written to: <path>.` A foreground subagent's task ends with that subagent's final response. `/tasks` lists and stops tasks; `TaskStop` takes the ID |
| Background `cd` | `Session cwd remains <dir>; directory changes made by the backgrounded command do not apply to subsequent commands.` |
| stdin | Not surveyed |
| Cancellation | The result carries `interrupted`. An SDK `AbortController` cancels the whole query. Signal choice, process-group cleanup, and orphan handling: Unverified |
| Memory cap | `CLAUDE_CODE_TOOL_MEMORY_LIMIT` applies a memory cgroup on Linux and WSL from `2.1.233`; the kernel kills an over-limit command and the result does not name the cap |

| Aspect | Behaviour |
|---|---|

### Sandbox

`Bash` only. macOS Seatbelt, or bubblewrap on Linux and WSL2; native Windows and WSL1 are unsupported. The default policy reads the host filesystem except denied paths, writes the working directory and the session temp directory, denies other writes, lets linked worktrees update the shared Git directory while protecting its hooks and config, and protects Claude settings, skills, hooks, MCP configuration, shell startup files, IDE settings, Git control files, and the credential directory even inside a writable root. Permission path rules and sandbox paths merge into one OS policy. Network filtering matches the requested hostname and does not inspect TLS. `Read`, `Edit`, `Write`, and `NotebookEdit` do not run inside the sandbox.

A sandbox violation is returned to the model, which can retry with `dangerouslyDisableSandbox`; that retry goes through permission handling, and `allowUnsandboxedCommands: false` removes it. SDK sessions that request sandboxing default `failIfUnavailable` to true.

### Approval

Modes are `default`, `acceptEdits`, `plan`, `auto`, `dontAsk`, and `bypassPermissions`. In the default mode `Bash` prompts except for a built-in set of recognised read-only commands. Rules parse compound commands and require each subcommand to qualify; the parser recognises common separators and strips a documented set of wrappers. Read-only forms of `ls`, `cat`, `head`, `grep`, `find`, `diff`, `stat`, `cd`, and Git run without a prompt. Ambiguous commands and commands over 10 000 characters prompt. A recognised file command is checked against `Read` and `Edit` path rules; an arbitrary interpreter that opens files is not, which is the stated reason for the OS sandbox. `auto` mode sends candidate actions to a safety classifier. `PermissionRequest` hooks can make the final decision and return modified input, which is checked again against deny and ask rules.

### Notable

- `PowerShell` is a preview tool on Windows. Its exit-code table differs: `where.exe` exit 1 is no match, `fc.exe` and `diff.exe` exit 1 is files differ, and `robocopy` has its own range.
- A recognised write command marks tracked reads stale; see Verification and mutation state.
- A `gh` command that hits a GitHub rate limit gets a `system-reminder` appended.
- Hook output strings are capped at 10 000 characters; larger text becomes a session file plus preview.
- No PTY and no streaming to the model.

## Search and listing

### Tools

| Tool | Arguments | Default caps | Ignore rules |
|---|---|---|---|
| `Glob` | `pattern: string`, `path?: string` | 100 files, sorted by modification time; `(Results are truncated.
